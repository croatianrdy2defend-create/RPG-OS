# ADMIN — Optional announced autosave (v0.9.7)

PLAY changes no canonical files between saves; a separately selected write-only log permits only its short append.

Autosave is off unless explicitly accepted in the campaign agreement. It invokes the protected complete-present ADMIN CHECKPOINT, not a background service or general PLAY write grant. The separately selected [write-only play log](PLAY_PERSISTENCE.md) performs one short append without persistence reads or checking. Autosave alone does not enable that log. Installation enables neither policy.

Cadence counts **completed PLAY replies since the last checkpoint**. Preserve the accepted campaign cadence. Appending a note resets no count; deferring a checkpoint does not disable that append. Use the observed conversation count, without reading the log or checking delivery every turn. At CHECKPOINT reconcile uncompiled notes and actual play once, then publish through ADMIN/CLOSE_CONTRACT and the working-log plan. An uncertain count stays uncertain; it does not create a delivery protocol or unattended save.

## Select once, preserve existing authority

During NEW_GAME include a selected policy in the compact proposal; for a bound campaign use ADMIN/RECALIBRATE.md. An explicit request to enable the documented standard policy accepts that policy; do not ask for the same acceptance again. A question or suggestion alone does not enable it. Keep the five existing agreement sections and named clauses; there is no sixth mandatory clause, new metadata field, save kind or controller record.

Optional prose in GM initiative:

> Autosave: Enabled under ADMIN/AUTOSAVE.md. Warn one response before automatically invoking a protected complete-present CHECKPOINT when consequential unsaved state or a substantial scene boundary makes it useful, after 15 completed PLAY replies since verified persistence, or at a supported context reading of 65% or more. Coalesce triggers; do not save an unchanged present or repeatedly trigger on an already handled high-context episode. The operator may defer, disable or save immediately. Preserve PC decisions, fictional time and the archive evidence boundary.

Put the brief warning/report preference in Presentation and the unchanged fictional moment and save-before-switch convention in Time and transitions. This grants persistence only, not generation, additional PC conduct, structural opacity, automatic REVIEW or stronger permissions. Missing or disabled policy means no automatic writes. Custom cadence/threshold needs an explicitly accepted change, not silent tuning. A non-writing reminder can still be offered at a substantial stopping point.

## Trigger and notice

Evaluate at a completed response boundary. Establish dirty state from actual accepted changes since the last verified save, including current private facts; merely reading a file, opening a host tool panel, speculating, or repeating an unchanged resolved attempt is not a change. Do not generate a fact to justify a save.

With unsaved state, any selected trigger may schedule one checkpoint:

- Consequential state: a material private determination needed for continuing play, obligation/relationship change, meaningful injury/resource/status change, discovery, active process or real random result needed later. Merely activating, updating or expiring an incidental baseline is not a new automatic checkpoint trigger. Routine shopping, transient extras and inconsequential texture need no individual save; once any accepted save trigger fires, the checkpoint still preserves the complete current active set.
- Substantial scene boundary: an actual transition already reached under the agreement; never end a scene just to save.
- Cadence: 15 completed PLAY replies since bind/verified persistence. Count replies containing resolved/portrayed play, not tool calls, OOC discussion, warnings alone or maintenance replies. Retain the observed count in working conversation; do not claim an exact count if unavailable.
- Context pressure: at least 65% from actual model-visible host telemetry or an explicit operator-reported reading. This is an early-warning convention intended to leave room before roughly 70%, not a measured safety guarantee. The player's visible meter need not be visible to the model. Unknown percentage stays unknown; never estimate it from conversation length or claim to monitor an unavailable UI.

Apply the selected early triggers to their significance, not merely the existence of a new fact. A new location, ordinary appointment, small purchase, incidental update or roll is not individually sufficient. A consequential trigger protects significant unsaved progress or a material change affecting continuing choices, resources, knowledge, relationships or processes; a substantial boundary completes or changes a meaningful activity with such progress. A materially important instance of an otherwise routine category can qualify. Coalesce eligible changes at the next announced operation, keep the accepted cadence/pressure triggers, and preserve all current state when saving. No per-turn trigger ledger or private-state write is added. Existing explicitly broader or custom campaign grants require accepted recalibration before narrowing them.

Coalesce all triggers and changed facts into a single pending notice. Give no additional notice for the same pending operation. Use a generic OOC message with no private fact, entity name or hidden trigger:

> OOC — Checkpoint after the next play response; “delay autosave” postpones it.

Explain manual-save/disable rights, the outgoing-save-before-switch convention and the checkpoint's evidence limit at initial selection or when relevant. Repeat that guidance only on request or a material change; it need not accompany every ordinary notice. These shorter notices change no switching, source-preservation or review requirement.

The notice is delivered one response before automatic execution. Never warn and automatically save in that same response, even under high reported pressure. Wait for the next user input; there is no unattended continuation. An OOC acknowledgment alone need not create fictional time or a PC action. Explicit “checkpoint now” or “save now” can execute immediately under the manual procedure. If pressure is already acute, recommend saving now rather than requiring another fictional turn; do not bypass the operator's authority.

A checkpoint does not empty the context window. After verified persistence during a supported high-context episode, mark that pressure episode handled in working conversation. Do not trigger again solely because the same high reading persists; rearm on an observed drop below the selected threshold or a clean fresh boot. Other genuinely new selected triggers still apply. Recommend full CLOSE and a fresh chat when pressure remains high instead of consuming the remaining space with repeated checkpoints. A user report is a reported snapshot, not continuous telemetry.

## Execute at an administrative boundary

A boundary means the current declared resolution and its tool operations have finished; it is not fictional safety. A dangerous scene or an unresolved PC choice can be checkpointed exactly where it stands. Do not require a trip to a safe location or resolve a pending choice to make saving convenient.

Before doing anything, check the exact RECOVERY/ACTIVE.md and HANDOVER/ACTIVE.md paths through their normal routes. Recovery has precedence; an active handover freezes source authorities. A second write, save, agreement change or recovery operation cannot run concurrently. Do not checkpoint the source from a receiving GM, and do not invent an alternative autosave target for it.

On the next eligible PLAY response after notice, resolve only the actual declaration, then invoke CLOSE_CONTRACT’s CHECKPOINT once through its selected executor. Preserve the complete present, current active set, consequential private state, Session continuity, unarchived feedback/input and existing useful preparation. Apply only lifecycle changes already established in play; serialization creates no new session, feedback interview, award or preparation.

CHECKPOINT retains archive_ref and evidence_through and creates no archive bodies/indexes/ledgers. ADMIN/CLOSE_CONTRACT.md owns publication and review selection: `tiered` is lightweight; `every-save` or a one-off checkpoint audit additionally uses EVIDENCE_AUDIT. That selected source tier may retain a raw capture without advancing the archive. Use one executor and its actual verification, not a second manual transaction.

Finish the completed action’s affected state before compilation; preserve unresolved choices. Do not reread the whole transcript at each cadence trigger or claim deferred review was completed. If selected review cannot finish, preserve valid progress with incomplete coverage and no audit loop. Clear physical-save scheduling after verified persistence; semantic incompleteness remains reported separately.

A scheduled decision is not a completed save. Clear the pending notice, dirty set and cadence only after actual verification; keep a handled context-pressure episode latched as described above. Briefly report the checkpoint id, retained evidence boundary and any material source limitation, without spoilers. Do not claim “lossless,” “all hidden facts recovered,” or “model switching is safe” from a structural pass or self-check. No fictional time passes and no extra turn is portrayed after the save.

Ordinary report format: `OOC — Checkpoint verified: <save_id>. History remains archived through <evidence_through>.` Use `none` when no history is archived. Add a short qualification for an actual source gap, failed/incomplete review or materially changed limitation. A routine lightweight readback is not a semantic PASS; explain its standing meaning once rather than repeating a lecture. Custom accepted reporting requirements still apply.

If a write/readback fails, retain the recovery marker, preserve the notice, and stop ordinary play for recovery. Do not reset the cadence, report success, silently retry in a loop or start another autosave. After recovery, reconcile whether the operation completed or was rolled back before deciding anything further. If writes are unavailable, report that and use the existing INSTALLATION export workflow; a warning or promised export is not persistence.

## Operator overrides and switching

"Delay autosave" suspends automatic execution in the current conversation until "resume autosave" or the next successful manual persistence operation, unless the operator specifies a different scope. Pressure never cancels the right to defer or stop. On resumption without persistence, cancel an old notice and announce again before the next automatic checkpoint. "Disable autosave" revokes permission immediately and persists the prospective policy through RECALIBRATE. A manual SAVE/CLOSE/END SESSION supersedes the pending checkpoint and remains a full save; never downgrade it. SAVE/bare CLOSE preserves the session; an explicit ending follows ADMIN/SESSION.md, including its feedback/unfinished-closure handling and full save, without waiting for another PLAY reply. A verified manual CHECKPOINT also clears the pending operation. These explicit requests need no preceding automatic warning.

Keep counters, notice/deferral and pressure-episode status in working conversation, not fictional records. Fresh boot starts at zero only at a fully compiled boundary. When uncompiled notes remain, recover the available completed-PLAY count once at boot; notes are not verified delivery counts, so retain uncertainty when needed. No per-turn log read or confirmation is added. Durable disabling remains in the agreement.

Treat a planned model, reasoning-setting, provider, chat or GM change as a persistence boundary, not automatically a play-session ending. Preserve its existing id and any unfinished wrap-up across the switch; only an actual ending request invokes SESSION. The outgoing context compiles and verifies the save first; do not recommend switching to a stronger model before saving. This is a conservative workflow, not a guarantee that any particular host erases or transfers context. Do not claim a universal context-retention capability.

A checkpoint protects current state only. Before discarding/replacing a chat, losing its source access, or transferring GM control, use a full CLOSE preserving available evidence or the existing SCENE_HANDOVER package/return procedure as appropriate. Do not call a checkpoint equivalent to archived dialogue. If the operator chooses a checkpoint-only transition, explicitly disclose the unarchived evidence limitation. The receiving model reloads the authoritative save, agreement, current active set and relevant records; a model switch is neither deactivation nor authority to regenerate active state. Fresh incidental activation is permitted only after genuine prior expiry under the accepted lifecycle and within retained facts. After an unplanned switch, use available saved/captured sources, report missing required state, and do not reconstruct unavailable private facts or rolls. A stronger model may audit already preserved state afterward under the existing review/evidence procedures; audit exposure does not itself make an incidental baseline permanent.

## Optional deterministic helper

TOOLS/autosave.py evaluates one caller-supplied observation and returns a scheduling decision. It has no campaign I/O, timers, save execution, model inspection or access to context meters. No script is required for ordinary play. Its input flags must reflect the accepted policy and actual observations, not an invented capability or a second authoritative state store. Reasons are diagnostic codes; keep the player-facing notice generic.

Example: `echo '{"enabled":true,"dirty":true,"turn":15,"turns_since_save":15}' | python -B TOOLS/autosave.py` returns `warn`. At that same turn with `warned_at:15`, it returns `wait`; with `turn:16`, it requests `checkpoint`. Neither request resets the supplied state or proves a save occurred. An integration must perform and verify CLOSE_CONTRACT before clearing the pending notice. Set `context_handled` after verified persistence during the current high-pressure episode; clear it only on an observed below-threshold reading or a clean fresh boot. Cancel the old `warned_at` when resuming a deferral without persistence so a new notice precedes execution. Reject malformed, duplicate, out-of-range or unsourced telemetry inputs rather than silently treating them as authority.

See the developer regression source at https://github.com/croatianrdy2defend-create/RPG-OS/blob/main/DEV/TOOLS/test_autosave.py for scheduler, route and synthetic metadata checks. https://github.com/croatianrdy2defend-create/RPG-OS/blob/main/DOCS/ADMIN/TEST_AUTOSAVE.md describes separate live behavioral cases; passing Python tests does not prove model compliance, hidden-state completeness or host-switch reliability.
