# ADMIN — Save the campaign

Cold persistence procedure. Read INSTANCE/_SCHEMA.md for record placement. This file owns compilation and review selection; the executor below owns publication.

**Selected write-only log:** follow [INCREMENTAL_SAVE](INCREMENTAL_SAVE.md) to reconcile uncompiled notes with actual available play and compile established changes. The helper protects current records and their exact compiled-log cursor together. Full SAVE preserves original source independently of the notes. An actual unmigrated journal uses the retained legacy ADMIN procedure.

## Commands and promise

**Save** and bare **CLOSE** mean a normal full save: preserve the complete current state and the available accepted evidence since the previous evidence boundary. An actual **END SESSION** request uses `ADMIN/SESSION.md` to consolidate developments, include feedback and adjudicate genuinely due engine procedures before invoking this same full save. Natural wording governs; “save and end” selects one wrapper, not two independent saves. A full save can preserve unfinished closure when the operator must stop or source access is at risk. No automatic REVIEW follows. Report the save result separately from any later explicit review.

**CHECKPOINT** is an optional present-only save. It preserves all current authorities, retains the prior archive_ref AND evidence_through, and writes no new archive bodies, indexes, or ledgers. Say plainly that new exact evidence was not archived. Do not offer a checkpoint as equivalent to a full save before discarding chat.

**Announced autosave** may invoke this same CHECKPOINT only under an explicitly accepted policy in `ADMIN/AUTOSAVE.md`. It adds no save kind or partial-state write path. A pending notice must precede automatic execution by a response; manual persistence supersedes it. Recovery and handover take priority. Clear pending operational bookkeeping only after actual write/readback verification; failures retain the recovery marker and stop ordinary play. A verified checkpoint is not a guarantee of complete hidden-state capture or host context retention.

**Scene handover** is a separate operation in `ADMIN/SCENE_HANDOVER.md`. It may checkpoint the complete present, then export the available conversation and GM briefing without claiming a new archive boundary. Check `HANDOVER/ACTIVE.md` before ordinary save/play: an active transfer is returned, cancelled or reconciled through that procedure, not advanced by a second GM. Importing an accepted return uses this full-save procedure and a retained receipt so later evidence preservation cannot apply the same changes again.

Saving never advances fiction, resolves an unanswered choice, ends a play session, adjudicates a boundary rule, authors or activates preparation, or interprets campaign direction. SESSION establishes any authorized boundary work before compilation. Preserve accepted post-save changes already in chat; do not infer goals, preferences, hidden events, or missing rules. Ordinary saves and checkpoints retain an active/closing/ended session as actually established; they create no new feedback interview or award opportunity.

## Shared save review: policy, cost and boundaries

All save routes use this procedure: manual SAVE/CLOSE, CHECKPOINT, announced autosave, explicit SESSION ending and accepted handover return. Shared routing does not mean equal review cost. Keep ordinary source-faithful compilation and write verification mandatory; the additional formal review follows the accepted policy in the existing agreement. Installing a release grants no capture, review or repair permission.

| Selected policy | Checkpoint, including autosave | Full SAVE/CLOSE, including END SESSION and accepted return |
|---|---|---|
| `off` or no standing option | Lightweight check below | Ordinary compilation/readback; formal source review only on explicit request |
| `tiered` (recommended when enabling save review) | Lightweight check below | Bounded source-first review under ADMIN/EVIDENCE_AUDIT.md |
| `every-save` (explicit higher-cost choice) | Bounded source-first review as well | Bounded source-first review |

An explicit “audit this checkpoint/save” selects one source review without changing future policy. A legacy grant for audit on full saves retains that scope; it does not enable transcript capture at checkpoints. A source review remains a fallible human/model judgment. Running the same reviewer more often does not remove its blind spots. Do not silently downgrade a selected source review under pressure or call a lightweight check semantic validation. Preserve progress and record an incomplete/deferred review with its exact save/source scope instead. No audit retry loop, extra PLAY turn or delay of an immediate stop is required.

The lightweight checkpoint check finishes recording the last completed action and checks its whole affected current surface: location and active participation after departure, money and settled obligations after payment, inventory after transfer, completed goals, unresolved choices, current state and once-only effects. Compare affected prior/proposed records, preserve unaffected facts and inspect metadata/routes. An available `TOOLS/evidence.py save-diff` can report selected byte changes and save parent/revision/evidence consistency; it does not determine what the dialogue means or prove an omitted record was selected. No raw capture, frozen audit bundle or source-first extraction is required at this tier. It therefore retains the cheap checkpoint path and existing autosave cadence; actual host cost and pacing remain unmeasured.

For the selected source tier, use ADMIN/EVIDENCE_AUDIT.md once over the new accepted source span and relevant owners. Its independent extraction detects omitted notes as well as unsupported additions. Reuse unchanged evidence; repeat only checks invalidated by a concrete correction and disclose incomplete coverage.

For each save, distinguish three boundaries:

- **State saved through:** the exact accepted stopping point of the proposed present. Prefer actual host conversation/message identity and revision; otherwise use an original capture hash and inclusive line span. If unavailable, preserve an honest description and gap, never invented identifiers.
- **History archived through:** existing `archive_ref` and `evidence_through`. A checkpoint retains both. A full save can archive dialogue already reflected in earlier checkpoints without applying its effects again.
- **Review covered through:** the actual selected source span, records and limitations in the external review receipt. Lightweight means no transcript-grounded review boundary. Never advance review coverage just because saving or archiving succeeded.

The small optional administrative `Save review` section described in INSTANCE/_SCHEMA.md may carry the proposed stopping-point description, requested tier and external receipt locator. It is not a second current authority or a success claim. Keep outcome receipts outside the candidate/bundle they reference; adding an approval afterward to a reviewed file would change its bytes and invalidate the review.

## Compile what changed

Identify accepted transitions since CURRENT_SAVE from working play and uncompiled notes, and the single current owner for each affected value. Begin from its compiled INSTANCE record; for a first change with no override, use only the specifically named MODULE as-of-T0 snapshot. Compile actual changes in one bounded pass, applying every still-unincorporated effect once and preserving the complete current mutable surface. A short note may precede delivery or omit nuance; actual available source resolves that scope. MODULE files remain unchanged. Do not resolve or charge an effect again merely to record it.

Prefer targeted edits to the actual prior bodies over regenerating whole records. Preserve unaffected wording and values where possible; a complete-present save does not require rewriting an unchanged file. For affected facts, reconcile who acted or spoke, when and where, who actually learned what, the scope of assent, attempted versus completed results, and once-only effects against available source. A changed quantity alone is no reason to rewrite unrelated history. Use a selected diff/readback to detect incidental alterations, while retaining the source-first review's independent search for omitted developments when that tier applies. These are compilation checks in the existing operation, not a new permanent action ledger or semantic guarantee.

Carry forward unaffected accepted facts and detailed sections without paraphrasing them at every save. For each accepted change, identify its current owner and, at full SAVE, surviving evidence. Compare the proposed changes with prior records and available play. Compilation and structural checking remain fallible; preserve qualifications and report actual gaps.

Prepare the five readable resume sections. Preserve actual ongoing action, meaningful unresolved decisions, remaining time where relevant, selected public conditions/resources, explicit live goals/obligations, operative processes, and exact useful routes. Follow the accepted agreement's continuation rules; a save boundary does not impose a new PC choice or erase one.

Also preserve administrative Session continuity, including its stable id, phase, opening basis, actual feedback disposition and unfinished items with original identities. Preserve required unarchived feedback/input at its available fidelity until a surviving evidence route can replace it. A newer session does not erase older follow-ups. Mechanical results and session/boundary/rule application references stay at their selected effect owners; beginning and ending remain distinct. Apply still-unsaved effects once, including a settled zero/inapplicable adjudication where relevant. Missing prior application evidence requires retrieval or honest pending treatment, never another award. A retry uses the retained intended target, not fresh adjudication.

Carry forward useful existing `INSTANCE/PREP.md` and accepted working revisions when present; create it only on authorized post-bind persistence when useful preparation exists. Do not manufacture a record, required categories or new future material to make the save complete. Keep its actual basis unchanged unless preparation really reconsidered that basis. PREP remains derivative; it cannot be the sole owner of feedback, session status, pending choices, hidden facts or a mechanical result. It is optional and is discovered by SESSION's fixed-path check, not a required current-authority route.

Preserve full PC details under CHAR, what the PC learned under KNOWN, private/system state and the active encounter set under NOW, enduring person/relationship progression under PEOPLE, id mappings under CAST_STATUS, and accepted rulings under CORRECTIONS. Do not replace detailed authority with a vague resume summary or duplicate a live total. If an emergent durable person/system first needs persistence, follow the schema's established-only record rules. An incidental active participant needs no person file or permanent id mapping. Keep a non-revelatory process cue only when needed for fresh-chat discovery; route the active block from Relevant records while it is needed to resume participation.

Preserve the actual active encounter set in NOW: each participant’s five established fields, precise limitations and useful actual method/change provenance, with references to enduring owners instead of duplicated values. Reuse unchanged entries. Apply only genuine lifecycle transitions already established in play: release expired inconsequential temporary values while keeping consequential facts and unresolved matters at their owners. A save performs no activation, deactivation or draw. A required missing active/consequential value is a source gap, not expiry or permission to reconstruct it. Use `OS/AGENT_STATE.md` only if this distinction needs resolution; no empty block or per-participant file is required.

For historical evidence, the boundary is the prior **evidence_through**, not necessarily the prior checkpoint. Gather only accepted source actually available from that boundary forward. A checkpoint may already have applied its state transitions; archiving those transitions now must not apply them to state again. Identify source gaps explicitly; a summary is not the missing dialogue or roll record.

## Full save evidence

Use ARCHIVE/_SCHEMA.md and preserve existing history. Create one new close folder with an INDEX and one or more coherent evidence bodies; split only for useful independent retrieval. Accepted-fiction bodies preserve available consequential wording, declarations, outcomes, quantities, chronology and uncertainty, excluding rejected/rewound fiction, unsent proposals, provider/ADMIN chatter and private preparation. The selected log helper instead retains explicitly labelled **original public source**, including OOC, as evidence of what was said; that label does not make every statement accepted fiction. Retain correction/disposition references without rewriting the original. Never export internal reasoning or provider instructions.

Actual player feedback, its disposition and relevant boundary adjudication may be retained as **OOC session operational evidence**, labelled with the applicable session and rule. Preserve actual wording and gaps without turning feedback into fictional events, knowledge, policy acceptance or population preferences. Save folders are evidence slices, not session boundaries; late feedback retains its original session identity.

If a full source is unavailable, archive only what the authoritative available record supports. Mark the missing span/detail and its limits explicitly in the evidence body; do not reconstruct it from model memory, current summaries, old hints, or expected continuity. A current private value may be defensible while its historical cause is unavailable; preserve that distinction. The public save report discloses a material source gap without leaking private content.

Indexes locate, source bodies establish detail. The campaign INDEX row carries the new save_id, close kind, folder, and session-index path. Keep routing terms compact and non-revelatory. A ledger entry is optional when it provides a useful direct route to exact wording or relationship evidence; ordinary relationships and intimacy do not require a special ledger entry. Never duplicate a complete exchange in a ledger or create a duplicate full-session transcript after faithful sharding. If safe partition is uncertain, retain a detailed coherent source and route to it.

## Choose one publication executor

Use the compatible helper for the selected working-log save through ADMIN/INCREMENTAL_SAVE.md. It executes recovery protection, staged writes, exact log-cursor publication and verification. Supply the compiled changes and selected review; inspect its result and return to play or stop. **Do not also perform the manual publication steps below or repeat a completed semantic review.** An incomplete or failed helper operation follows its recorded recovery route.

Where that helper is unavailable or incompatible, the manual executor below preserves the same guarantees. Never bypass a selected log binding or ignore outstanding notes to force the fallback; resolve that compatibility gap first. Both executors preserve progress with honestly incomplete source/review coverage when necessary.

## Protected write order

1. Finish recording all accepted consequences of the latest completed action, without completing an unanswered action or choice. Identify the exact source stopping point and selected review tier. Build the intended complete save and affected record changes in working context. Assign a unique save_id, increment save_rev, and set save_parent to the accepted prior id. Full save uses commit_kind `close`, new archive_ref, and evidence_through equal to the new save_id. CHECKPOINT uses `checkpoint` and copies both prior evidence metadata values unchanged.
2. Where the host can safely assemble a stable complete proposed save outside the live root, perform the selected source review before publication, using preserved prior authorities and the exact available source. A changing mixture of old and new files is not a frozen candidate. Recheck the accepted live parent and affected preimages immediately before publication; a changed parent/write set requires a new candidate and review. A known corrupt proposal is not published as usable: retain new progress/evidence separately while resolving it. Missing evidence or an unavailable reviewer is a disclosed incomplete review, not permission to lose otherwise valid progress. Where a stable candidate is unavailable, preserve prior versions and perform bounded review after the protected save; clearly state that ordering.

   Follow ADMIN/RECOVERY.md: record the entire file and directory sets, preserve and verify all existing-file preimages, list new archive/candidate/body paths and every required new parent directory with verified pre-existence, and create the active marker before campaign writes or directory creation. Protect safety/PC/index files too if affected. Record directories actually created by this operation. If this fails, leave campaign files untouched.
3. Write `INSTANCE/CURRENT_SAVE.candidate.md`, the selected complete current bodies and any useful modified PREP. Include Session continuity, effect-owner application references and required feedback in the declared protected write set. Do not write the agreement or Bearing. An accepted agreement amendment uses RECALIBRATE before compiling its dependent save; do not hide it in this operation. Only an explicitly requested safety/correction change may add its separately authorized affected files to this operation.
4. Full save only: write evidence bodies, session INDEX, campaign INDEX row, then any useful ledger pointers. CHECKPOINT writes none of these.
5. Inspect the candidate and actual assembled write set. Confirm each changed fact has one current destination, accepted transitions were applied once, required sections and metadata are complete, every affected path resolves, and archive/evidence identity agrees. Confirm active membership and complete required values match the actual stopping point, expired entries have no competing current copy, retained consequences still have an owner, and gaps/uncertainty were preserved. Compare session identity, phase, pending items and effect references with their prior authority and accepted work; received feedback is not proof that a proposed change was accepted. PREP's basis must reflect actual preparation, not an automatic save stamp. The current pointer still names the earlier save, so do not report a whole-tree structural PASS at this intermediate stage.
6. Replace CURRENT_SAVE last. Read it and the affected routes again. Where a frozen reviewed candidate exists, compare actual selected bytes and declared removals with it (`TOOLS/evidence.py check-save-audit`); any changed candidate requires fresh review, not reuse of its prior approval. Verify new id/revision, parent, evidence boundary, the intended state, and the recorded directory set. Finish the recovery record and remove its active marker only after successful checking. Preserve preimages and recovery history. Restoring a failed save also resolves operation-created empty directories through the exact nonrecursive cleanup in ADMIN/RECOVERY.md; file restoration alone is insufficient.
7. Confirm OOC: full save or checkpoint, new save_id, where exact evidence now reaches, review tier/result/coverage and any material source limitation. Report physical save success separately from semantic consistency or source coherence. A lightweight result is not a transcript-backed PASS; a pending source review is not a failed physical write. No fictional time passes. An explicit REVIEW request is separate.

If anything fails before or after pointer replacement, keep the active marker and follow ADMIN/RECOVERY.md. An older CURRENT_SAVE alongside separately overwritten newer bodies is not a playable old save. A new CURRENT_SAVE beside missing bodies is not a successful new save. Neither the candidate nor CURRENT_SAVE-last provides atomicity or automatic rollback.

## Historical corrections and later maintenance

Never silently rewrite immutable accepted history to make a later correction look as though no error occurred. Use ADMIN/CORRECT.md to preserve a narrow superseding correction and repair the affected present. A request to undo a valid accepted outcome follows the agreement's Retcon clause; saving itself grants no rewind or ironman exception. Rejected fictional material is not reintroduced as an event. Optional archive reindexing or lossless partition is a separate protected maintenance operation; retain original source whenever equivalence is uncertain.

### Reorganize growing current records

Use an explicit maintenance request or an accepted bounded standing grant; installation and ordinary save permission alone do not authorize reorganization. Consider it when unrelated completed material repeatedly obstructs needed retrieval, useful sections cannot be selected economically, or superseded current copies compete. File size or a session count alone is no mandatory trigger. Finish any save/recovery first and preserve the same fictional moment.

1. Select only the affected current owners and their inbound routes. Distinguish resume essentials, operative facts and surviving consequences, detailed knowledge, and historical event sequences. Completion alone does not retire knowledge, relationships, promises, beliefs or unresolved effects.
2. Propose a concise current entry and exact subordinate routes using the existing INSTANCE layout. Prefer lossless partition of detailed authority; no new universal index, archive or summary format is required. Keep established facts, qualifications, chronology, identity and access scope. Relocate a historical sequence out of current prose only when surviving accepted evidence covers it at the required fidelity and its consequences remain discoverable. Otherwise retain its full detail in a routed current record.
3. Protect the full before/after and directory sets through RECOVERY, including every route changed. Retain an explicit old-section-to-new-route mapping in that operation. Preserve referenced anchors as routing stubs or update their inbound references; a stub is not a competing copy of the fact. Do not rewrite immutable archive evidence or delete old sources to make equivalence appear true.
4. Compare relocated passages exactly where partition is lossless and review any changed cues against their source. Check all changed routes and a small relevant retrieval/resumption sample, including a retained historical cause, a live commitment and any active encounter in scope. Label untested or uncertain coverage. Byte equality alone does not prove that the right information remains discoverable.
5. Publish the checked owners/routes under RECOVERY, read them back and retain preimages/mapping. Complete source-faithful reorganization or restore the protected prior state if equivalence cannot be established. Do not resolve fiction, refresh temporary NPC state, mint a new play session or change save/evidence identity merely to reorganize files.

A full save requires no campaign interpretation, new plot, general repository audit, or exhaustive lore rereading. Use the available accepted source and exact changed authorities, and preserve what is unknown.

## Source review integration and retained evidence

ADMIN/EVIDENCE_AUDIT.md owns the source-first comparison, stable inputs, actual reviewer arrangement, corrections and exact receipt checks. Use relevant original sources as well as the edit list; a wholly omitted promise appears in no diff. A changed candidate invalidates only affected review coverage, and publication must match the final reviewed bytes. Preserve valid progress with disclosed incomplete coverage when required sources or review are unavailable.

A selected source review may retain an authorized raw capture under EVIDENCE even at a checkpoint; this neither publishes accepted history nor advances archive_ref/evidence_through. Reuse exact captures and reconcile overlapping source by actual identity/span, never wording alone. Repairs follow CORRECT and existing authority; saving or audit does not authorize a rewind.

The optional EVIDENCE store is an exception to ARCHIVE's prohibition on duplicate accepted-history transcripts: it preserves original OOC, superseded and rewound source for review, not another canon or current save. An enabled incremental journal likewise retains source/proposed material for its recovery/evidence duties, without making every retained draft accepted history. Normal PLAY does not preload captures/audits. No additional review grants automatic REVIEW, general repository scans or full-archive rereads.
