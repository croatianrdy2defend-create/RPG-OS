# Quick start — v0.7.3

## Prepare the folder

Download the [v0.7.3 release](https://github.com/croatianrdy2defend-create/RPG-OS/releases/tag/v0.7.3), extract it into a dedicated folder, and give your model access. The kit is unbound: there is no world or character yet. Only Freeform is included.

The host should read, write, preserve, and inspect ordinary files. If it cannot write, use the manual export steps in [INSTALLATION](INSTALLATION.md). Keep one campaign per copy.

## Start a new campaign

Say:

> Open OS/AGENTS.md. Help me start a new RPG campaign. Use Quick start and ask only what you need next.

Give any premise, character, preferences, rules, or references you already have. The GM reuses them, asks only for the next necessary choice, and proposes the playable minimum. Guided and Detailed setup are also available.

Review the concrete campaign agreement and opening. Ordinary clear acceptance is enough. The GM then creates the selected records, checks them, and reports the campaign/save identity. Start a fresh play chat afterward, or continue with the accepted bound material.

## Resume and save

In a fresh chat with the campaign folder available:

> Open OS/AGENTS.md and continue my saved campaign.

At a stopping point:

> Save the campaign and end the session.

SAVE, CLOSE, and END SESSION all perform the full save. Wait for confirmation before discarding chat history.

For an explicitly reduced save:

> Make a checkpoint.

CHECKPOINT preserves the present but does not advance the archive evidence boundary. It is not a substitute for full session evidence.

## Switch the GM during a scene

With a bound campaign, say:

> Prepare a scene handover at this point.

The GM pauses at the unresolved input and prepares two separate records: available conversation and established GM state. Any missing history is identified. It checks the package before confirming readiness.

Give the receiving GM access to the same coherent workspace copy and say:

> Open OS/AGENTS.md and receive the active scene handover.

Do not continue the source copy in parallel. The receiving GM verifies the package and explicitly takes over; it does not restart the campaign from its last archive. When ready to return, ask it to prepare the scene return.

Back with the source GM:

> Import the completed scene return and continue from its resume point.

Import checks identities, changes, and repeated event IDs before applying a protected update. Its factual return record uses non-graphic wording. A transfer can also be cancelled before import. See [Scene handover](ADMIN/SCENE_HANDOVER.md) for the complete procedure and conflict handling.

## Correct or adjust play

Say what was wrong:

> That contradicts the earlier scene. Correct it without changing the unaffected play.

Or request a prospective change:

> I want to adjust the pacing and GM initiative.

The GM uses the appropriate correction or agreement procedure. If a recovery marker is present, it reconciles the interrupted operation before normal play.
