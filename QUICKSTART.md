# Quickstart (one page)

1. Attach only the RPG_OS folder to a writable project/workspace. New chat. Strong model. Product name does not prove persistence; run the preflight.
2. Paste:

Open only OS/AGENTS.md, OS/BOOTSTRAP.md, OS/LAW.md, INSTANCE/CURRENT_SAVE.md. Do not list the folder. Confirm ready. No scene.

3. Optional: `VALIDATE`. With code execution, expect a `SCRIPT-VERIFIED` STRUCTURAL result plus a tree digest; HOST OBSERVATION must remain `NOT RUN` and SEMANTIC must remain `NOT CHECKED`. Without code execution, the result must say `MODEL-CHECKED` with exact coverage: `INCOMPLETE` unless the inspection found a definite defect and reports `FAIL`.
4. Optional: Begin play. It must refuse.
5. New game. Pick a ruleset first. Set any extra safety boundaries before detailed drafting. Choose world/campaign depth (Sparse is default), character/profile depth, and whether to defer, minimally complete, fully build, or import a mechanical sheet. A completed sheet is optional. Complex systems and PC shards are also optional. Pick a starting scenario, review the manifest, say Accept, then ADMIN commits and binds.
6. NEW chat, same folder:

Open only OS/AGENTS.md, OS/BOOTSTRAP.md, OS/LAW.md, INSTANCE/CURRENT_SAVE.md. Voice section if fiction starts. Begin at the save. Hand back before my first act.

7. Play. You write the PC. At a break: CHECKPOINT (saves the present). Before ending the day: CLOSE (present + scene-sharded exact evidence).
8. Next session = new chat + step 6. Do not paste old chat. Do not leave until ADMIN prints the new save_id.

OOC tools: AUDIT (what files/sections opened) · VALIDATE (read-only structural diagnostic) · CHECKPOINT (present) · CLOSE (present + indexed scene archive)

UI suggested-reply chips are not your move. Ignore them.

Preflight: a heading-only quote does not prove isolation. If PRIVATE leaks, split files. After CHECKPOINT, a new chat must show the new save_id or this host cannot persist.
