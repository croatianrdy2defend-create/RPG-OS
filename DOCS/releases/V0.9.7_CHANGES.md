# RPG OS v0.9.7 — practical pacing and long-campaign maintenance

## Same-version update — 14 September 2026

- New campaigns now propose `Incremental recording: write-only-log` as the standard persistence profile by default. After each completed PLAY response, the GM appends one or two concise factual outcome sentences without rereading persistence files or performing per-turn semantic verification. Players can decline or customize this during setup.
- New campaigns now propose announced CHECKPOINTs every **20 completed PLAY replies** by default. One generic warning precedes the automatic checkpoint on the following eligible response. Consequential-state, substantial-scene-boundary and supported context-pressure triggers remain optional early triggers that require separate acceptance.
- Normal END SESSION SAVE waits for closing feedback or an explicit skip, then performs the session-ending full save. The GM explains and preserves permitted adjustments for the next session; no second save command is required. Explicit requests to save immediately and concrete imminent source-loss cases retain truthful unfinished feedback.
- Short command reminders at session start and end explain SAVE, CHECKPOINT, END SESSION SAVE and ordinary OOC requests. Setup, Quickstart, command reference and beginner instructions follow the same order.
- Existing bound campaigns keep their previously accepted logging/autosave policy unless explicitly recalibrated; updating the kit does not silently retrofit those agreements.
- Software version remains **v0.9.7**. The current game-only distribution is `game-v0.9.7-r2`; `r2` is a packaging revision, not a software-version bump. The original `game-v0.9.7` release remains a frozen earlier build.

## Same-version update — 13 September 2026

- **2026-09-13, same-version continuity and performance update:** Optional write-only PLAY notes, checkpoint compilation and source-reviewed full saves gained separate, bounded jobs. Normal logging appends one or two outcome sentences with no persistence reads or per-turn verification. At this stage of v0.9.7, installation enabled neither logging nor autosave by default; the 14 September same-version update above changed the default proposal for new campaigns.
- Full-save completion requires the existing source-bound review evidence; stale compilation bases are rejected. Original public wording and specific correction links are retained, while delivery remains distinct from accepted fiction. Archived source boundaries and required handover dependencies survive host-file moves with explicit source limitations where needed.
- Saving selects one helper or manual executor. Setup, cadence resumption and reusable instructions are consolidated. Source export reuses one stable parse per source within an operation; passage fetch verifies the selected source; routine validation hashes its declared campaign-text scope, with whole-workspace checking still available explicitly.
- Version remains **v0.9.7**. Earlier tagged downloads are preserved; use the current `main` GAME files or the current `game-v0.9.7-r2` game-only distribution for these same-version changes. Existing campaigns require protected program updates and retain their accepted recording policy and records. Regression checks establish storage behavior, not guaranteed response latency or long-campaign semantic reliability.

## Changes

- Announced autosave uses shorter ordinary notices and clearer significance criteria for early triggers. A new fact, location or roll alone is insufficient; important instances can still qualify. Selected cadence, supported pressure thresholds, advance notice, manual overrides, complete-present scope and evidence boundaries remain. Existing custom grants require accepted recalibration before narrowing.
- Ordinary execution within an authorized activity continues to the next meaningful reserved decision or interruption. Chosen experiences receive actual perceptible substance. This grants no new PC action, cut, expenditure, response to danger or mandatory emotional beat.
- Save compilation prefers targeted changes to prior authoritative bodies, retaining unaffected wording where possible. Source review checks attribution, chronology, possession, knowledge, assent and once-only consequences while still looking for developments entirely omitted from a proposed edit list.
- Growing current records have a protected maintenance path within CLOSE_CONTRACT. An explicit request or bounded standing grant can authorize lossless partition and route repair. Historical evidence, qualifications, surviving consequences and current encounter state remain intact; no automatic rewrite at a session count or file-size threshold.
- Session preparation connects supported causes, actual participant concerns, due versus possible developments and the accepted campaign spirit. Feedback becomes a concrete prospective change in GM conduct, with actual application distinguished from copying a note. No new questionnaire, compulsory scene or event quota.
- NEW GAME, optional detailed preparation and Quick start present these choices within the existing compact agreement. Program installation does not silently amend existing campaigns.

## Evidence helper

`TOOLS/evidence.py metadata-template` emits correctly typed editable caller claims with unknown conversation completeness. `citation` extracts original lines, their hash and exact line endings from a verified frozen bundle. It rejects unavailable sources, tampering, unsafe paths, invalid ranges and capture citations beyond a bound save's endpoint.

CLI JSON uses ASCII escapes to round-trip Unicode under legacy stdout encodings. Source and capture bytes remain UTF-8 and unchanged. Neither helper determines relevant evidence, manufactures a source delivery, certifies comprehension or supplies a reviewer verdict. Existing report-template, capture, source-review and saved-byte verification remain compatible.

## Existing campaigns

Back up the campaign and use [the protected upgrade procedure](../../GAME/ADMIN/UPGRADE_V08.md). Install program files without overwriting current state, the agreement, PC, installed modules, evidence or historical records. Then apply any separately accepted prospective policy changes through RECALIBRATE. Existing autosave cadence, review choice, source rules and generations remain selected unless the operator changes them.

The current playable package is published as `game-v0.9.7-r2`; `r2` is a same-version distribution revision. The original `game-v0.9.7` package remains a frozen earlier build, and older version tags and assets remain intact. [Game-only distribution](../DISTRIBUTION.md).

## Verification scope

New deterministic cases cover metadata defaults and rejection, exact citations across source sides and line endings, tampered/unavailable sources, range/path rejection, legacy-encoding CLI output and save-boundary enforcement. Existing regression and standalone distribution suites also apply. Final results are recorded in [Verification](../VERIFICATION.md).

These are software checks, not a new multi-session campaign trial, a measured cost reduction or evidence of session-100 reliability. The existing published v0.9.5 playtest remains historical evidence of its own run. No private campaign transcript or state is included in this release.

The following optional behavioral probes remain **NOT RUN for v0.9.7**: whether a GM consistently shortens authorized routine without skipping a new decision; whether a genuinely fresh GM preserves an active encounter after lossless record partition; whether real play shows sustained feedback uptake and lower administrative cost. Run only a relevant bounded probe when needed, keeping source, expected preservation and observed outcome distinct.
