# v0.9.6 — Tiered, source-bound save review

2026-09-11. Experimental protocol and optional tooling release.

**This is improved save routing and evidence binding, not a solution to fallible model review.** The source-first audit methodology already existed. Applying it consistently does not remove same-model blind spots, demonstrate semantic detection accuracy or establish session-100 reliability.

## Review cost is an explicit choice

All saving routes reach the existing CLOSE_CONTRACT procedure. The recommended opt-in `tiered` policy keeps ordinary/manual/automatic checkpoints lightweight: finish recording the completed action, compare affected records, preserve unanswered choices, check save identity and read back writes. Full saves, explicit session endings and accepted handover returns use a bounded source-first review. Explicit `every-save` adds that more expensive review at checkpoints; one-off audit requests retain their one-off scope. Installing an update enables no policy and grants no new capture or repair permission.

Lightweight checking creates no raw transcript or frozen audit package and does not claim semantic verification. Missing source, insufficient review budget or unavailable reviewer produces explicit incomplete/deferred coverage, not a silent downgrade, fabricated PASS, retry loop or loss of otherwise valid progress. Existing autosave cadence, notice and context-pressure behavior are unchanged. Actual model cost and live pacing are unmeasured.

## Three separate boundaries

- **State saved through:** the accepted stopping point the proposed present should reflect, using actual source identity and revision or an honest gap.
- **History archived through:** the existing archive_ref/evidence_through pair. Checkpoints retain it; later full saves archive earlier checkpointed dialogue without applying its events again.
- **Review covered through:** the source span/selected records actually reviewed, including limitations. This never advances merely because saving or archiving succeeds.

Optional administrative provenance may point to an external review receipt without asserting success. No required save field, agreement clause, second world-state store or new engine rule is added. Legacy saves remain readable and are not retroactively labeled reviewed.

## Concrete checks and honest limits

TOOLS/evidence.py adds `save-review-plan`, read-only `save-diff`, `prepare-save-audit` and `check-save-audit`. They validate policy input, selected differences, save parent/revision/identity, checkpoint archive retention, capture stopping-point bounds, frozen write/removal scope, review references and exact selected saved bytes. Changed candidates cannot reuse an earlier review. Prior-only evidence selections are not automatically treated as deleted files. Existing capture/general-audit interfaces remain compatible.

A model or human still extracts consequential developments from original source before inspecting the writer's answer, checks omissions and additions, and judges evidence meaning. Active-chat/transcript overlap is not a second event. An attempt is not success, testimony is not world truth and private knowledge is not public disclosure. Tools do not independently perform those judgments. A separate source-coherence field can preserve a reviewer-observed contradiction; copying contradictory narration does not repair it. The original correction and consequence-containment rules retain authority over repairs.

Autosave's old blanket raw-transcript prohibition is explicitly amended: ordinary lightweight checkpoints still create none, but a selected source review may preserve an actual EVIDENCE capture without writing accepted-history archive bodies or advancing evidence_through. A chat visible to the player is not proof that the host supplies it to the reviewer.

Where supported, review a complete stable proposed save before publication; otherwise disclose post-save review. Existing recovery protects writes. Final selected-file readback ties a report to what was actually saved. Known corrupt candidates are retained separately rather than published as usable. Neither current-pointer-last nor byte matching promises atomicity or perfect memory.

## Compatibility and distribution

No core engine/world rules, existing campaign history or public unbound templates are rewritten. The selected review policy is adopted prospectively through the existing agreement. Source captures and private audit receipts remain outside public distribution. The earlier public TEST_REPORTS directory stays in GitHub history but is excluded from the fresh-install ZIP; all selected kit files are still verified against their committed blobs and other unexpected tracked campaign content is rejected.

See [the shared save procedure](../../GAME/ADMIN/CLOSE_CONTRACT.md), [audit schema and commands](../../GAME/ADMIN/EVIDENCE_AUDIT.md), [verification](../VERIFICATION.md) and [behavioral cases](../ADMIN/TEST_SAVE_REVIEW.md). Deterministic tests are not a blind semantic playtest, a measured model-latency benchmark or evidence of human enjoyment.
