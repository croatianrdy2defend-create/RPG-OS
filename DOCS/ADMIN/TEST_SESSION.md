# Developer cases — session continuity and feedback

Cold, optional diagnostics for v0.9.5. Ordinary play does not run this checklist. Use isolated noncanonical fixtures and actual source/procedure routes; no fixture, invented transcript, reward or test person enters a campaign. Structural validation is distinct from model behavior. Record actual observations, source gaps and unrun cases, with the build/model and host capability actually known.

## Connected cases

| Case | Sequence | Observe |
|---|---|---|
| S01 | Quick NEW GAME, Guided setup, or existing-module LOAD | The same session duties fit the ordinary agreement; neutrality precedes worldbuilding. No extra interview, session id, PREP or played history at bind. |
| S02 | Bind, readiness only, then immediate end | Preserve/save and stop without inventing a played boundary, retrospective or award opportunity. |
| S03 | First play, Save, fresh-chat resume, mid-scene handover | One logical session persists; a fictional choice stays pending. Saving/context change does not request end feedback or award. |
| S04 | Engine with a genuine beginning hook; then resume | Apply once at the actual new-session trigger, with distinct session/boundary/rule reference. Resume only completes identified unfinished work. |
| S05 | Normal end with actual feedback | Stop fiction, consolidate, receive feedback, connect its permitted treatment to preparation, adjudicate actually due procedures once and verify the full save. |
| S06 | Feedback supplied before end | Reuse it; do not repeat answered questions or turn an in-character wish into an OOC preference. |
| S07 | Explicit feedback decline | Record the decline and finish closure without inventing preferences or requiring answers. |
| S08 | Immediate stop before feedback | Full-save truthful pending items; preserve the actual moment and any owed invitation. An immediate stop is not a decline. |
| S09 | Feedback question with no answer or completed save | Never claim received/saved. Preserve full available state before an actual source-loss/stop trigger where possible; no claim of unattended action. |
| S10 | Late feedback after another session begins | Preserve original feedback identity and newer current session, update applicable prospective preparation, repeat no previous mechanics. |
| S11 | Repeat END after a zero/inapplicable ruling | The settled adjudication is retained; only unfinished work or requested persistence remains. Missing PREP does not make the award unpaid. |
| S12 | Cancel ending before/after ending adjudication | Before settlement the same session may resume; after settlement preserve it and begin the next on actual play. An earlier beginning procedure is not an ending settlement. |
| S13 | Missing engine source or reserved spending choice | Preserve precise pending work, no guessed award/reset/purchase; complete unrelated authorized saving/feedback. Freeform creates no XP. |
| S14 | PREP absent, stale or from another campaign | Rebuild/ignore derivative notes from authority without losing causes, actual feedback or application records; unsafe routes are not followed. |
| S15 | Ordinary save with unchanged preparation | Preserve complete state and unchanged actual preparation basis; no false fresh-review stamp. |
| S16 | A completed concern, then a quiet continuation | Preserve completion and its consequences; require no replacement threat, clue/cast count or escalation. |
| S17 | Checkpoint, then full save with partial source access | Required current feedback survives; archive only available actual evidence and qualify gaps, without reconstructed exact dialogue. |
| S18 | Inject a save failure, recover and retry | Protected targets and owners reconcile, CURRENT_SAVE publishes last, no duplicate adjudication or premature success. Use disposable copies only. |
| S19 | Legacy adoption and clean packaging | Preserve unknown earlier coverage and exact state; no backfilled session/test history. Public output has neither runtime PREP nor live session control. |

| Case | Sequence | Observe |

## Recording a result

Hold source facts and player inputs fixed when comparing behavior. Keep explicit feedback separate from the GM's interpretation and the candidate adjustment. Record whether execution used one context or independently initialized contexts, supplied rules/results or actual retrieval, and real file operations or only a conversational rehearsal. Do not call a source-text assertion a session test or a scripted walkthrough a population/long-campaign result. Reuse valid observed coverage; rerun only affected or unresolved cases.
