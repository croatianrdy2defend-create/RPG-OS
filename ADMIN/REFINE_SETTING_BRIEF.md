# Refine or repair a Setting Brief

Cold ADMIN procedure after a request to improve the module's public startup orientation. Use the existing brief and narrow stable public sources, keeping its module identity and three standard sections.

Distinguish a clearer restatement from an actual change to the world. A restatement must preserve accepted facts, qualifiers, distribution, and uncertainty. Show any proposed new fact separately for explicit acceptance; do not conceal it in editorial wording. A correction to established campaign facts follows ADMIN/CORRECT.md and may require dependent repairs.

Draft the complete compact replacement and explain the material differences with exact supporting pointers. Useful improvements include the opening scope, reality differences generic priors would erase, ordinary variation, and when a concrete form needs deeper authority. Do not add a roster, current mutable state, secrets, clock bodies, planned scenes, or a reading checklist.

After acceptance, use ADMIN/RECOVERY.md for the affected files, replace the brief, and read it back. Inspect every changed depth route. If a module descriptor must change, disclose and include it in the accepted affected set; do not leave a dangling capability.

An interrupted write leaves the operation pending for recovery. Preserve the old version. A useful valid brief needs no revision merely because the OS version changed. Script validation is optional and cannot prove the summary's fidelity.
